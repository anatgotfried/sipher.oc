The Problem

Agents interrupt you
in the worst possible ways

Chat scrollback buries decisions. Approval prompts arrive without context. There's no reliable way to loop a structured response back to the agent.

💬
Decisions buried in chat
Critical approvals scroll past in conversation threads, mixed with status updates.
A dedicated Needs Me feed surfaces only what requires your action.
🙈
Approvals without context
"Should I send this?" — but the agent never shows you what "this" actually is.
Approval cards must include the exact draft, diff, command, or attachment.
🔄
No structured feedback loop
Your decision goes into the void. The agent can't reliably act on it programmatically.
Every button press records a structured event and can trigger a webhook.
🔒
Everything goes to the cloud
Agent tools that require subscriptions or phone-home to external services for private workflows.
Sipher runs locally. Zero external dependencies. Self-hostable via Tailscale.
How It Works

Three moves. Closed loop.

1

Agent creates a card

Your agent POSTs a structured card via HTTP or CLI — with type, context, priority, and the exact content needing review.

Agent
2

You decide

Sipher surfaces the card in your Needs Me feed. You approve, reject, answer, or choose — with full context right there.

Human
3

The loop closes

The action is recorded as a structured event. If the card has a callbackUrl, Sipher POSTs the result immediately.

Structured Event
Card Types

A type for every agent moment

Agents pick the right card type. Each one has a defined schema — so you always know what you're looking at.

✅
Approval
Approve or reject an action. Requires the exact content: email draft, diff, command, purchase, or attachment.
🔀
Choice
Pick from a defined set of options. The agent waits for one clear signal before proceeding.
❓
Question
Answer a free-text or structured input field. Unblocks the agent with a typed, record-able response.
📊
Status
An agent progress update that doesn't need action. Keeps you informed without asking for anything.
🗞
Briefing
A multi-item summary — morning brief, project recap, or end-of-day rollup — with bullet items and source links.
⚖️
Comparison
Side-by-side options with structured fields. Built for architecture decisions, vendor comparisons, and tradeoff analysis.
Built Right

Designed for real agent workflows

🏠

Local-first, zero friction

No accounts. No cloud services. Runs on localhost:4173 with a single npm start. Your data stays in a local JSON file.

🔗

Webhook feedback loop

Add a callbackUrl to any card and Sipher POSTs the full { card, event } payload the moment you act. Agents can poll or listen.

🤝

Multi-agent ready

Hermes, OpenClaw, Atlas, Calendar Agent, Deploy Agent — any agent that can POST JSON can surface cards in the same shared feed.

📱

PWA on any device

Mobile-first layout. Add to home screen. Expose privately over Tailscale Serve to approve cards from your phone while the agent runs on your desktop.

⏱

Expiration & freshness

Cards with expiresAt auto-archive when they lapse. /api/version lets agents verify they're talking to the right, current instance.

🛠

HTTP API + CLI

Full REST API for card creation and action recording. CLI wrapper for scripting, seeding demo data, and running simulations from the terminal.

Quick Start

Up in 30 seconds

Requires Node 18+. Clone the repo, install, start the server — then seed the demo feed to see Sipher in action immediately.

✓ Zero config, zero external services
✓ Demo cards seeded instantly with npm run seed
✓ Multi-agent simulation via npm run simulate
bash 
# Clone and install
$ git clone https://github.com/anatgotfried/sipher.oc
$ cd sipher.oc
$ npm install

# Start the server
$ npm start
# Open http://localhost:4173

# Seed demo cards
$ npm run seed

# Or run a multi-agent simulation
$ npm run simulate

# POST a card from any agent
$ curl -X POST localhost:4173/api/cards \
  -H 'content-type: application/json' \
  -d @examples/approval-card.json
Multi-Agent

One feed. Any agent.

Sipher doesn't belong to one agent. Any tool that can POST JSON can surface a card. Multiple agents share one clean feed — each card is clearly owned, and cross-agent context lives in structured metadata.
